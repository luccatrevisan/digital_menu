## 31/07/2026 - Implement user addresses API
### Goal
Allow authenticated users to register and list their delivery addresses.

### Implemented
- Address Serializer
```python
from apps.users.models import Address
class AddressSerializer(serializers.ModelSerializer):
    class Meta:
        model = Address
        fields = "__all__"
        read_only_fields = ["user"]
```
 
- Address View
```python
class AddressView(generics.ListCreateAPIView):
    authentication_classes = [JWTAuthentication]
    permission_classes = [IsAuthenticated]
    serializer_class = AddressSerializer

    def get_queryset(self):
        return Address.objects.filter(user=self.request.user)

    def perform_create(self, serializer):
        serializer.save(user=self.request.user)
```
 
- urls.py
```python
urlpatterns = [
    # added:
    path("api/address/", AddressView.as_view(), name="api-address")
]
```
 
### Key Decisions
- **What use does the perform_create function have?**
  Inside view.py, I chose to use this function to associate the user creating the address to the address. This is a way to avoid malicious intent from a user trying to creating addresses related to others.

- **Why use ListCreateAPIView for Address?**
  Because I will only use the GET and the POST methods. As the business owner, I decided to treat updated addresses as a whole new one to avoid deleting the order history with that address. It is a business decision. So, the view only needs to have two methods: to Create and to List.

### Challenges
1. Which permission class should I use in the address API?
   - **What I learned:** I stopped to think about some rules related mostly to security. First, an user should not be able to see other people's addresses. Second, the user should be authenticated, since they can only see the address related to their account.
   - **What I decided:** The most important thing is to avoid other users to see address that are not theirs. So, I used get_queryset to filter addresses only related to them. If none, they will create one so they can conclude their order - but that is a problem for another task.
