- Improved the ValidationError returns on orders/serializers.py
```python
def validate_items(self, items):
    if not items:
        raise serializers.ValidationError(
            detail={
                "message" : "The cart cannot be empty.",
                "code" : "empty_cart"
            }
        )

    for item in items:
        try:
            menu_item = MenuItem.objects.get(pk=item["menu_item_id"])

            if not menu_item.is_available:
                raise serializers.ValidationError(
                    detail={
                        "message" : f"{menu_item.name} is not available.",
                        "menu_item" : f"{menu_item.name}",
                        "code" : "item_unavailable"
                    }
                )
            
        except MenuItem.DoesNotExist:
            raise serializers.ValidationError(
                detail={
                    "message" : f"Menu item {item['menu_item_id']} does not exist.",
                    "code" : "item_does_not_exist"
                }
            )

        try:
            stock = Stock.objects.get(menu_item=menu_item)
        
            if stock.quantity < item["quantity"]:
                raise serializers.ValidationError(
                    detail={
                        "message" : f"Only {stock.quantity} units available.",
                        "menu_item" : f"{menu_item.name}",
                        "remaining" : f"{stock.quantity}",
                        "code" : "stock_unavailable"
                    }
                )
        
        except Stock.DoesNotExist:
            pass

    return items
```

### Key Decisions
- **Why I chose to change the ValidationError returns:**
  Because this way the error handling on the frontend can be simpler and clearer. If I want to change an error message to something else, I wouldn't need to change the frontend too now that the javascript uses the "code" parameter that comes from the API request. Also, I can return more information depending on the error. If, for example, the user were ordering an item that the company doesn't have enough stock, I should tell them how much they can order.

- **Why I chose to remove the login-warning on the HTML:**
  Because the login page already has a message warning the user that they have to be logged in to order. I thought that it may improve the user experience if I just send them directly to the login page if they are not authenticated instead of just sending a simple warning.

### Challenges
1. Figure out why the frontend was not returning any error messages.
   - **How I solved it:** I was having problems figuring out what exactly the API was returning. My solution was to install Postman (I had Postman previously when the development environment was set on Windows) to be able to send multiple requests (api/token/ and api/orders/) more easily and see what I was getting back from it.
   - **What I learned:** I am able to change the return myself. I was using built-in solutions from Django like ValidationError to deal with it and could use Response. But, this is only in views. I got deeper on my understanding of ValidationErrors and found out that there are two different types: one that is Django-related and another that is Serializer(DRF)-related. The return of both of them are different and have to be treated differently. For the serializer, I could change more stuff and add information related to the error. But, for the Django ValidationError I couldn't do much without making a messy response.
