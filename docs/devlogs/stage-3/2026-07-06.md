- changes on the renderMenu() js function 
```javascript
function renderMenu(data){
    const container = document.getElementById("menu-container");
    container.innerHTML = "";

    data.forEach(category => {
        if (!category.menu_items || category.menu_items.length === 0) return;
        const categorySection = document.createElement("section");
        categorySection.classList.add("category");
        const categoryTitle = document.createElement("h2");
        categoryTitle.classList.add("category-title");
        categoryTitle.textContent = category.name;
        const itemsContainer = document.createElement("div");
        itemsContainer.classList.add("items-container");

        category.menu_items.forEach(item => {
            const itemDiv = document.createElement("div");
            itemDiv.classList.add("item");
            if (!item.is_available) {
                itemDiv.classList.add("unavailable");
            }
            itemDiv.innerHTML = 
            // CHANGES HERE: now, the image gets the static path that comes from the Model with CharField instead of the media that comes from ImageField 
            `
                <img src="/static/${item.image}" alt="${item.name}">
            `;
        });
    });
}
```
 
### Key Decisions
- **Why I chose to deploy on Railway:**
    I really liked the services that they provide, like having the PostgreSQL database embedded in the same project and the synchronism that the app has with Git and GitHub. I realized during the deployment that, when I do a git push on the project, Railway automatically starts the build. I liked that.

- **Why deploy now:**
    Despite being away for a while to get some rest, I kept learning and found out that I don't really need AWS, Docker, Kubernetes or CI/CD to deploy a project. My initial thought was that I really needed these technologies just to have my project public to the world. That is also the reason that the digital_menu roadmap had Docker and a DevOps section. I was mistaken.

- **Where are the products images?**
    I was up for learning about cloud services like AWS S3, but i thought that it would be a lot of work for a moment that requires a simpler approach. I'd rather get a simple solution like changing the ImageField from the MenuItem model to CharField with the image path. 
    
    Since I have only one store, the images don't tend to change in a few years and there isn't a need to change them a lot of times, I choose to save the product images as static files.

    For the future, I can use a AWS S3 bucket or something related to cloud services, but for know the application is intended to be really simple, using the file's path to get the image

### Challenges
1. Realized that the dotenv file works differently in production environment. How exactly is Railway using them?
   - **How I solved it:** Used the variables section from Railway on the digital_menu project
   - **What I learned:** The first Railway documentation recommended creating the variables on setup/settings but it didnt make sense to me because their values would be public. I had to find my way through the railway website to find the variables section.

2. Had some problems to deploy the application from the GitHub repository
   - **How I solved it:** A lot of researching in the Railway docs and exploring the website itself.  
   - **What I learned:** My main problem was that I couldn't understand the official guides. Maybe because they explore a more generic approach - with a really simple project - instead of something real. I got really confused with the docs but eventually I realized that I just needed to set my variables on Railway instead of changing them on my code.  

3. Problems with the Railway Postgres database
   - **How I solved it:** The solution was to just change the variable names to match the Railway ones. Before, I was using something like DB_USER and, for deploy, Railway was using PGUSER. I changed it on my code - also on my dotenv file, for development environment - and made the correct configuration on Railway.
   
   Also, I had to give some thought about how I would feed the database, since It would be on the Railway Cloud. 
   - **What I leaned:** I had to customize my build and my pre-deploy commands on Railway because of the static files and the migrations, respectively.
